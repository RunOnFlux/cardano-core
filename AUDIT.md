# cardano-core audit — 2026-09-30

Scope: `@runonflux/cardano-core` 0.1.0, every file under `src/`. Method: differential testing against the libraries it replaces (cardano-serialization-lib 14.1.2 and cardano-message-signing 1.1.0, the exact versions ZelCore ships), a mainnet transaction corpus, RFC and CIP test vectors, a line-by-line self-review (§4), and five rounds of independent review on 2026-09-29 and 2026-09-30 whose findings are all fixed (§9).

## 1. Verdict

**Ready to run behind a flag in ZelCore, not yet ready to be the default.** The independent reviewer rates it releasable behind the flag, provided the integration meets the four conditions in §9.5. Every byte the library produces that ZelCore relies on is proven identical to CSL/CMS, and every transaction id matches the chain on 3,110 mainnet transactions. Five rounds of independent review (§9) found the send path sound and raised findings in the dapp-facing and robustness code — round 1: eleven (one high, three medium), round 2: six (one high: collateral theft), round 3: two (one medium: collateral destruction), round 4: three (one low–medium: a collateral-cap bypass), round 5: two low (hardening of the cap and its opt-out) — all fixed with regression tests. One thing remains before the flag flips (§7):

- **No funded mainnet transactions yet.** CSL accepts every plan (value conservation, min-ADA, `min_fee`), but no node has accepted one. ZelCore's rollout plan includes micro-transaction checks for every flow.

## 6. What is not verified

- **Node acceptance.** No transaction built by this library has been submitted to mainnet. CSL is a strong but not independent judge: a formula both get wrong (min-ADA, linear fee) would pass. Both formulas are taken from the Babbage/Conway ledger specs, and CSL is what ZelCore has shipped for years, so the shared-assumption risk is low but not zero.
- **Reference-script fee** is checked against hand-computed tier values only, not a node. ZelCore skips reference-script UTXOs by default, so it is not on the default path.
- **Dijkstra era.** The decoder keeps unknown body keys, but an unknown key inside a map-form _output_ is rejected (the transaction cannot be signed until the library learns it). This is deliberate: better to refuse than to display a partial output.
- **`requiredSigners`** assumes Conway's `reg_cert` (tag 7) needs the stake key's witness, per the Conway ledger rules; it was not checked against a node.
- **Side channels.** Signing uses noble's constant-time scalar multiplication. Derivation uses JavaScript bigint arithmetic, which is not constant-time; the attacker would need local timing access.
- **Zeroisation** is best-effort (`zeroize`, `LocalSigner.destroy()`); JavaScript engines may keep copies.
- **`describeTransaction` cannot see input values** without a UTXO lookup. It reports what leaves (outputs to others, fee, deposits, donation) and what enters (withdrawals, refunds) separately; a prompt should headline `totalOutflow`. Deposits for certificates without an explicit amount (tags 0, 1, 3) use the parameters passed in (default mainnet); a pool re-registration is counted as a new deposit (conservative).
- **Generic `decodeCbor` without `maxBytes`**: duplicate-key tracking is linear, but an input that nests composite keys _and_ makes their fingerprints collide at every level costs up to depth (128) × size in hashing. `decodeTransaction` caps input at 64 KiB; other callers of untrusted CBOR should pass `maxBytes`.
- **`requiredSigners`** cannot attribute inputs without a UTXO lookup; the payment key is assumed for our inputs.
- **Collateral judgement needs the wallet's context.** A collateral return is recognised as ours only through `ownAddresses` (now required), and collateral inputs are valued only from `ownUtxos`; anything the wallet cannot value is refused, and a transaction without a return is accepted only with a stated `total_collateral` within the cap — `ownUtxos` completeness is never relied on. A `total_collateral` inconsistent with the inputs and return is not re-checked: the ledger rejects such a transaction in phase 1, so no collateral can be taken.
- **Byron rules follow the ledger, not CSL**, where they differ: any explicit protocol magic means testnet (CSL reports an explicit mainnet magic as mainnet), and the attribute limit is the ledger's HD-payload-plus-unknown-attributes measure. Checked against the ledger source, not against a node.
- **Fee minimality** is checked by the oracle (fee = ledger minimum + folded dust on every plan) and by exhaustive neighbour search at the 2^32 width boundary (review 2 INFO); the refinement tries the fees at each smaller size and at every CBOR width limit of the residual output.
- Hashed CIP-8 payloads, bootstrap witnesses, Plutus spends, certificates and governance building are out of scope (0.1.0 refuses or does not offer them).
